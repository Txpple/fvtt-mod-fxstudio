# The look grammar (schema 2)

This is the one grammar FX Studio reads and writes (ARCHITECTURE §4, §7). The screens compose it
from pickers, an assistant writes it as data, the files hold it, and the module reads all three the
same way. `scripts/core/looks.js` is the code; this page is the grammar with every knob's meaning,
range and default, for a person or an assistant writing a look by hand.

The sentence is generated from the look, never parsed back:

```json
{ "id": "fire-bolt",
  "for": ["spell:fire-bolt"],
  "on": "use",
  "scenes": [
    { "shape": "shoot", "asset": { "path": "jb2a.fire_bolt.orange" },
      "sound": { "asset": "psfx.cantrips.fire-bolt", "volume": 0.75 } }
  ],
  "by": "the migration", "at": "2026-09-06", "note": "D&D5e Animations 3.3.0" }
```

reads as *Fire Bolt · when used · a bolt (JB2A fire bolt, orange) shoots from the caster to each
target and flies past on a miss · with the PSFX cantrips fire-bolt sound.*

## The files

| File | What | Licence |
| --- | --- | --- |
| `baseline/spells.json`, `weapons.json`, `natural.json`, `features.json`, `items.json`, `effects.json` | the migrated D&D5e Animations corpus, one file per subject kind, read-only, regenerated by `tools/migrate-aa.mjs` | GPL-3 (`BASELINE-LICENSE`) |
| `house.json` | the user's looks and overrides; `tools/export-looks.mjs` folds the world buffer into it | MIT |
| `starters.json` | the abstract looks every new look starts from (`starter:bolt`, …) | MIT |
| `aa-assets.json` | the frozen asset table: what the migration could not point at the libraries' own paths; counted, meant to reach zero | MIT |
| the world setting `looks` | the live edit buffer the screens and the API write | — |
| an item's flag `fvtt-mod-fxstudio.look` | the item pointer: one specific item names a look id of its own (set from the screens with "only this one"); it answers ahead of every key, and such a look has an empty `for` | — |

Every file is `{ "_meta": {...}, "looks": [look, …] }` with `_meta.schema: 2`. Resolution order:
the world buffer, then `house.json`, then the baseline — later wins per look id, and per subject key.

## A look

| Field | Required | Meaning |
| --- | --- | --- |
| `id` | yes | lower-case letters, digits and dashes; unique across the corpora. A house look with a baseline look's id replaces it. |
| `for` | yes (may be empty for a starter) | the subject keys it answers, see *Keys*. A look answers the first key of a subject's list that has a look. |
| `on` | yes unless `like` | the moment kind: `use` (an ability used — the attack roll for attacks, the damage roll for saves and heals, the template placement for areas, the card for the rest) or `effect` (an active effect created or switched on). |
| `like` | no | inherit everything not stated from another look (its id) or a starter (`starter:bolt`). A chain is allowed. |
| `with` | no | overrides applied after inheriting: `asset` (the first picture's asset), `colour` (every picture's colour), `sound` (a path, a sound object, or `null` to silence), `opacity`, `scale` (multiplies every size). |
| `off` | no | `true`: this look silences its `for` keys — they play nothing. Needs no scenes. |
| `scenes` | yes unless `like` | the pictures and sounds, in start order. |
| `by`, `at`, `note` | no | provenance: who wrote it (a name, an assistant, "the migration"), the ISO date, and why in a sentence. |

A look needs a placed template when any of its scenes is a `fill` or names `template` as a place;
with two looks for one key, the one that needs the template answers a template moment and the other
answers the rest.

## Keys

`<kind>:<id>`, optionally `/<activity type>` for the most specific form. The reader builds a subject's
keys most specific first; a look is found by the first key that has one.

| Kind | Id | Example keys, most specific first |
| --- | --- | --- |
| `spell` | dnd5e's identifier (`system.identifier`, else the slug of the name) | `spell:fire-bolt/attack`, `spell:fire-bolt` |
| `weapon` | the slug of the name, then the base weapon (`system.type.baseItem`) | `weapon:maul-of-momentum`, `weapon:maul` |
| `natural` | the slug of the name (a weapon whose type is natural) | `natural:bite` |
| `feature` | dnd5e's identifier | `feature:brutal-strike` |
| `item` | the slug of the name (consumables, equipment, tools, loot) | `item:potion-of-healing` |
| `effect` | the slug of the effect's name, then its origin's keys | `effect:shield`, then `spell:shield` |
| `status` | the status id (phase 4) | `status:prone` |
| `damage` | the damage type (phase 4) | `damage:fire` |
| `event` | the event (phase 4) | `event:riposte`, `event:turn-start` |

The slug is Foundry's strict slugify after dnd5e's identifier rule: lower case, letters, digits and
dashes, everything else dropped ("Melf's Minute Meteors" → `melfs-minute-meteors`,
"Blindness/Deafness" → `blindness-deafness`). A trailing qualifier is tried after the whole name:
"Misty Step - Spellcasting" also gives `spell:misty-step`; "Potion of Healing (Greater)" also gives
`item:potion-of-healing`. A "cast spell" activity puts the linked spell's keys first; an ammunition's
keys come before the weapon's. Nothing is ever matched by a substring or a word.

## A scene

`shape` says what the picture does; every other knob is named for what it does and means the same in
every shape. Only the knobs a shape reads are allowed on it (the validator names any other).

| Shape | The picture | Reads |
| --- | --- | --- |
| `strike` | a swing at the caster, rotated toward each target and moved toward it when out of reach; can miss; `thrown` swaps in a flight beyond reach | common, `from`, `to`, `size {tokenWidths}`, `mirror`, `onMiss`, `thrown` |
| `shoot` | a picture stretched from a place to a place; can miss; a return flight | common, `from`, `to`, `mirror`, `onMiss`, `return`, `scatter`, `clearTemplate` |
| `mark` | a static picture at a place, sized to the token, as a radius, in squares, or to the placed object; once or persistent | common, `at`, `size`, `mask`, `persist`, `attach`, `follow`, `face`, `rotate`, `aboveLighting`, `mirror`, `onMiss` |
| `fill` | a picture sized to the placed template's shape (circle, cone, line, rectangle) | common, `at` (always `template`), `size {fit: "shape"}` or `{squares}`, `mask`, `persist`, `rotate`, `aboveLighting`, `xray`, `clearTemplate` |
| `aura` | a persistent picture attached to a token, sized as a radius, breathing and pulsing | common, `at`, `size {radius}`, `persist`, `attach`, `breathe`, `pulse` |
| `beam` | a picture attached at both ends, standing until ended | common, `from`, `to`, `persist` |
| `move` | the token itself: fades, travels or jumps to the destination | `sound`, `delay`, `range`, `pick`, `speed`, `fade`, `after`, `jump`, `checkCollision` |
| `sound` | a sound on its own | `asset`, `volume`, `delay`, `start`, `repeat`, `every`, `wait` |
| `custom` | the escape hatch: Sequencer calls as data against a whitelist; read as "a custom effect" | `calls` |

**Common knobs** (every picture shape): `asset`, `sound`, `delay`, `wait`, `repeat`, `every`, `rate`,
`fadeIn`, `fadeOut`, `opacity`, `tint`, `below`, `elevation`, `zIndex`, `anchor`, `note`.

### Assets

| Form | Meaning |
| --- | --- |
| `"jb2a.fire_bolt.orange"` or `{ "path": "…" }` | a library path (JB2A's, PSFX's or the frozen table's own registration) |
| `{ "paths": ["…", "…"] }` | one of several, chosen at random each time (library paths or raw files) |
| `{ "file": "modules/…/x.webm" }` | a raw file |
| `{ "family": "jb2a.fire_bolt", "colour": "orange", "variant": "01" }` | the same path in parts |
| `{ "byPosition": { "center": …, "mid": …, "left": … } }` | three assets, picked by where the template sits against the caster (a thunderwave); pairs with `rotate: "by-position"` |
| `+ "colour": "black"` | a colour swapped into the path's last segment; the family must list it (`tools/assets.mjs` shows what it lists) |
| `+ "template": [grid, start, end]` | Sequencer's stretch metadata for this picture, only where the migration had to keep AA's |

A sound is `{ asset, volume, delay, start, repeat, every, wait }`; `volume` 0.75, `delay` 0, `start`
0 ms into the file, `repeat` 1, `every` 250 ms.

### Places

`source` the caster · `each-target` every targeted token · `targets-else-source` the targets, or the
caster when nothing is targeted · `both` the caster and the targets · `template` the placed template
· `destination` the spot a move goes to · `impact` where the previous scene's pictures landed, per
target, a miss included · `area` a random spot inside this look's standing area picture, else the
caster.

`at` is for a picture that stays put; `from` and `to` for one that travels.

### Sizes

`{ "tokenWidths": n }` n token widths (the token as drawn, image scale and ring included) — a swing
is 5, a mark 1.5 · `{ "radius": r, "plusToken": true }` r squares around, the token's own width added
when asked · `{ "squares": n }` n grid squares · `{ "fit": "shape", "scale": {x, y} }` the placed
template's measured shape · `{ "fit": "object", "scale": n }` the placed object's bounds.

### Timing and look

| Knob | Meaning | Default |
| --- | --- | --- |
| `delay` | ms before the scene starts (negative starts it early against the previous wait) | 0 |
| `wait` | `true`: the next scene starts after this one finishes (plus `delay` ms); a number: after that many ms | false |
| `repeat`, `every` | play the picture n times, ms apart | 1, 250 |
| `rate` | playback speed | 1 |
| `fadeIn`, `fadeOut` | ms | mark 250/500, aura 250/500, others 0 |
| `opacity` | 0–1 | 1 |
| `tint` | `{ colour, contrast, saturation }` | none |
| `below` | under the tokens | false |
| `elevation` | `{ level, absolute }` | the token's |
| `zIndex` | draw order among pictures | 1 |
| `anchor` | `{ x, y }` | 0.5, 0.5 (a cone or line fill: 0, 0.5) |
| `mirror` | `"random"` flips the picture at random; `"none"` | strike and shoot: random |
| `onMiss` | `fly-past` (a bolt flies past), `play` (a swing plays as a miss), `skip` | shoot: fly-past; strike, mark: play |
| `persist` | `none` · `effect` (while the tying effect stands) · `template` (while the Region stands) · `until-removed` | mark and fill: none; aura and beam: until-removed |
| `attach` | `{ alpha, visibility }`: a persistent picture follows the token's fading and hiding | both false |
| `follow` | a once-only mark that still follows its token while it plays | false |
| `face` | `"away-from-source"`: the mark points away from the caster | — |
| `rotate` | degrees, or `"by-position"` (a fill turned to where the template sits) | 0 |
| `mask` | clipped to the token or the template | false |
| `scatter` | a bolt lands a little off the mark | false |
| `clearTemplate` | the placed template is removed once the scene has played | false |
| `aboveLighting`, `xray` | drawn above lighting; seen through walls | false |
| `return` | `{ asset }` a flight back from where the bolt landed (shoot) | — |
| `thrown` | `{ asset, return: {asset}, sound, reach }` what flies when the target is beyond reach; `reach` "auto" (five feet, plus one square for a reach weapon) or squares | — |
| `breathe`, `pulse` | `{ min, max, every }` an aura's scale and opacity loops | — |
| `range`, `pick`, `speed`, `fade`, `after`, `jump`, `checkCollision` | a move: feet of range; `click` or `movement` (the token's own move); grid squares per second when travelling; `{to, after, back}` the token's fade; ms before the token is placed; place it (true) or travel (false); refuse a blocked spot | 30, click, 120, none, 0, true, false |

### Custom

`calls` is a list of `[method, ...args]` run on the Sequence in order: `["effect"]`, `["sound"]` and
`["animation"]` start a section, `["wait", ms]` waits, anything else is called on the current
section. A place word in an argument (`"source"`, `"each-target"`) is resolved to the moment's
tokens. Only the methods in `CUSTOM_WHITELIST` (core/looks.js) are allowed. Rare by design: a knob
every look can use is always better than a custom scene one look uses.

## Writing a look: the assistant's round trip

1. `node tools/census.mjs` — what plays nothing, per sheet, with each subject's keys.
2. Pick a starter (`starters.json`) or an existing look to be `like`.
3. `node tools/assets.mjs "misty step"` — the libraries' own families, variants and colours; a path is looked up, never guessed.
4. Write the look as data. The whole authoring model for most looks is one line: `{ "id": "sharran-step", "for": ["spell:sharran-step"], "like": "misty-step", "with": { "colour": "dark_black" } }`.
5. `node tools/check-looks.mjs <file>` — every problem in a sentence; every asset against the registration and the disk.
6. `node tools/preview.mjs <file or look id>` — plays it on the sandbox fixture.
7. Propose it: in the game through `api.looks.save(look, {by})` (into the world buffer, with provenance; a person exports it to `house.json`), or as a change to `house.json` in a pull request.
